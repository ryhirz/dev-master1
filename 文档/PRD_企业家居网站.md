## 一、项目概述

### 1.1 背景

客户为一家家居（家具）企业，需要建设官方网站以展示企业实力、产品系列、品牌故事与典型案例，并通过「在线留言」获取用户咨询与应聘线索、通过「招聘入口」发布社会/校园招聘信息。当前缺乏统一的数字门户，品牌形象分散、内容更新低效。

参考站点「蓝鸟家具官网」是一个典型的**企业品牌展示 + 招商/留言询盘**型官网，无电商交易能力。本项目以前台官网 + 后台管理系统为整体目标，形态在参考站基础上按客户确定的导航结构重构（新增案例展示与招聘入口、移除招商加盟），并采用 FastAPI + React 技术底座，便于后续演进。

### 1.2 业务目标

1. 建立专业的企业官方门户，统一品牌形象与内容出口。
2. 通过产品中心、案例展示、新闻资讯、关于我们等栏目建立品牌信任。
3. 通过招聘入口发布社会/校园招聘，吸引人才；通过联系我们收集用户咨询。
4. 通过后台管理系统让非技术人员可自助维护内容，降低运营门槛。

### 1.3 产品定位与范围（v1）

- **前台官网**：面向终端消费者、求职者、媒体等公开访问者，纯展示 + 留言/询盘，**不含电商交易**。
- **后台管理系统**：面向企业内部运营人员，负责内容（产品、案例、新闻、招聘、关于我们、轮播、留言）与权限的增删改查。
- **主导航（5 个，固定）**：首页 / 产品 / 新闻 / 招聘入口 / 关于我们；其中 4 个主导航下挂二级导航（见信息架构）。

### 1.4 品牌标识（Brand Identity）

为统一前台官网与后台的品牌表达，明确以下品牌基本信息（与导航原型 `prototype_topnav.html` 保持一致）：

| 项 | 内容 | 说明 / 使用位置 |
| --- | --- | --- |
| 中文品牌名 | **Rz家居** | 全站站点名、浏览器标题（title）、页脚署名、后台页眉 |
| 英文品牌名 | **Rz HOME** | 英文标语 / 国际化占位（与中文名搭配呈现） |
| 字母组合（Logo 字标） | **Rz** | 顶部导航 Logo 图形中的字母组合 |
| 品牌标语 | **家居美学** | 与英文 "Rz HOME" 搭配，呈现为 "Rz HOME · 家居美学" |
| 品牌名状态 | **已确定** | 早期版本曾以 "TP" 作为占位简称，v0.4 正式更名为 Rz家居 |

说明：

- "关于Rz" 栏目（企业概况/公司简介）的品牌名即指本节的 Rz家居；该栏目内容由后台「关于我们配置」模块维护（见 5.12）。

### 1.5 非目标（Non-goals，v1 明确不做）

1. **不做在线商城**：不含购物车、在线下单、支付、订单履约。（原因：参考站为纯展示+询盘模式，且电商涉及支付合规、库存、物流，复杂度高，应作为独立后续项目。）
2. **不做前台会员体系**：前台访客匿名浏览，仅通过留言表单留资。（原因：v1 阶段会员价值有限，避免需求膨胀。）
3. **不做多语言 / 国际化**：v1 仅中文单语种。（原因：目标市场以国内为主。）
4. **不做 CMS 自定义页面装修**：页面结构由开发固定，运营仅填内容。（原因：控制范围与排期。）
5. **不做营销自动化 / 私域运营工具**：如短信、邮件营销、企业微信集成等留作后续。（原因：属独立增长项目。）
6. **不做招商加盟（经销商加盟）**：v1 主导航已不包含招商加盟，相关加盟留资能力从 v1 移除（详见附录「范围变更说明」）。如后续需要，作为独立模块在 v2 加入。

## 二、目标用户与用户故事

### 2.1 用户画像

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 终端访客（消费者） | 浏览家具产品、了解品牌与案例 | 快速找到心仪产品系列与案例、了解企业实力 |
| 求职者 | 关注企业招聘的社会/校园人才 | 查看招聘职位、了解企业与投递意向 |
| 内容编辑 | 企业内部运营 | 维护产品、案例、新闻、关于我们、轮播图内容 |
| 客服/HR 人员 | 企业客服或人事岗 | 查看并处理联系留言、维护招聘职位与应聘线索 |
| 超级管理员 | 企业 IT/管理者 | 管理账号、角色权限、查看数据 |

### 2.2 用户故事（标准格式）

**前台**
- 作为终端访客，我希望在首页快速看到品牌亮点、推荐产品与最新动态，以便建立第一印象。
- 作为终端访客，我希望在「产品中心」按系列/空间筛选产品，以便找到所需品类。
- 作为终端访客，我希望在「新案例展示」查看典型项目/客户案例，以便评估企业实力。
- 作为终端访客，我希望在「新闻」下分别浏览企业新闻与行业资讯，以便获取相关信息。
- 作为求职者，我希望在「招聘入口」查看社会招聘与校园招聘职位，以便投递意向。
- 作为求职者，我希望在职位详情页直接投递意向，以便 HR 收到带职位信息的应聘留言并跟进。
- 作为用户，我希望在「关于我们 → 联系我们」提交咨询留言，以便获得回复。

**后台**
- 作为内容编辑，我希望在后台新增/编辑/下架产品、系列、案例、关于我们内容，以便保持官网内容更新。
- 作为内容编辑，我希望发布/撤回新闻资讯（区分企业新闻/行业资讯），以便对外传递品牌动态。
- 作为 HR/客服，我希望在后台维护招聘职位（社会/校园）并处理联系/应聘留言，以便跟进线索。
- 作为超级管理员，我希望创建管理员账号并分配角色（编辑/客服），以便分工协作且互不越权。
- 作为超级管理员，我希望查看内容量与留言量的统计概览，以便了解运营情况。

## 四、前台官网功能需求（逐栏目）

> 优先级：P0=必须上线，P1=重要但可快速跟进，P2=后续考虑。

### 4.1 首页（P0）
- **功能**：聚合展示品牌亮点、推荐产品、最新案例、最新新闻、招聘入口；顶部为轮播 Banner。
- **页面元素**：导航栏（5 主导航）、轮播图、品牌一句话定位、企业实力数据（来自 company_info：建厂年份/荣誉数/生产线数等，可配）、推荐产品卡片、最新案例、最新新闻列表、招聘入口 CTA、页脚（联系方式/版权/备案）。
- **验收**：
  - Given 后台配置了轮播图，When 访客打开首页，Then 首页按排序展示生效的轮播图。
  - Given 后台标记了推荐产品，When 访客打开首页，Then 展示对应推荐产品卡片并跳转详情。
  - Given 后台配置了企业实力数据，When 访客打开首页，Then 展示对应数据，未配置时不展示该区块且不报错。

### 4.2 产品 → 产品中心（P0）
- **功能**：系列列表 + 分类筛选 + 产品列表 + 产品详情。
- **页面元素**：
  - 系列列表页：各系列卡片（封面、名称、产品数）。
  - 产品列表页：支持按系列、空间分类、关键词筛选，分页。
  - 产品详情页：主图+图集、名称、型号、简介、规格参数、所属系列/分类、相关推荐。
- **验收**：
  - Given 访客选择「胡桃禮」系列并筛选「卧室」，When 提交，Then 仅返回该系列下卧室类产品。
  - Given 产品被后台下架（status=hidden），When 访客访问列表/详情，Then 不展示（详情返回 404 或提示已下架）。

### 4.3 产品 → 新案例展示（P0）
- **功能**：案例列表（可按分类筛选：住宅/工程/商业）+ 案例详情。
- **页面元素**：案例卡片（封面、标题、分类标签）、详情（图集、描述、项目信息）。
- **验收**：仅 status=active 的案例对外可见；标记为「新」的案例可在列表优先展示（P1）。

### 4.4 新闻 → 企业新闻 / 行业资讯（P0）
- **功能**：新闻列表按分类（company=企业新闻 / industry=行业资讯）展示 + 详情。
- **页面元素**：列表（封面、标题、日期、摘要）、详情（正文富文本、发布时间、分类标签）。
- **验收**：仅发布状态（published）的新闻对外可见；草稿不展示；分类切换正确过滤。

### 4.5 招聘入口 → 社会招聘 / 校园招聘（P0）
- **功能**：职位列表按类型（social=社会招聘 / campus=校园招聘）展示 + 职位详情；提供「投递意向」入口。
- **页面元素**：职位卡片（标题、部门、城市、薪资、类型标签）、详情（职责、要求、投递入口）、招聘说明区。
- **投递意向（v1 即支持，非 P1）**：访客在职位详情页点击「投递意向」，提交姓名*、电话*、邮箱、内容，后端以 `message.type=job_application` 且 `ref_id=该职位 id` 落库，进入后台留言管理「应聘留言」分类，由 HR/客服统一查看与跟进。
- **验收**：
  - 仅 status=active 的职位对外可见；类型切换正确过滤。
  - Given 访客在职位详情提交投递意向，When 提交成功，Then 后台留言管理出现一条 type=job_application、ref_id=该职位的记录，HR 可见职位关联信息。

### 4.6 关于我们 → 关于Rz / 发展历程 / 品牌介绍 / 联系我们（P0）
- **关于Rz（企业概况）**：图文展示公司简介、实力数据（来自 company_info：建厂年份/荣誉数/生产线数等，可配）。（Rz 为品牌名。）
- **发展历程**：时间轴展示企业关键里程碑（milestone 表驱动）。
- **品牌介绍**：品牌理念、工艺（人体工程学/原创设计/智能生产线/售后服务）等（about_section 表中 code=brand 区块驱动）。
- **联系我们**：公司信息/电话（company_info）+ 在线留言表单（姓名*、电话*、邮箱、内容*），提交进入后台留言 `type=contact`。
- **验收**：以上四页内容均由后台「关于我们配置」模块驱动；未配置时显示默认占位文案，不报错。

### 4.7 全局（P0/P1）
- **响应式适配（P0）**：桌面 / 平板 / 手机自适应，移动端导航折叠（主导航 + 二级抽屉）。
- **SEO 基础（P1）**：各页 title/description、语义化标签、sitemap、静态化或可索引。
- **页脚与备案（P0）**：版权、ICP 备案号占位、联系方式、主导航快捷入口。

## 五、后台管理系统功能需求

### 5.1 登录与权限（P0）
- **功能**：管理员账号密码登录（JWT），按角色控制菜单与操作权限；AccessToken 过期可通过 RefreshToken 续期。
- **角色**（权限范围见下表）：

| 角色 | 权限范围 |
| --- | --- |
| 超级管理员 | 全部权限（含账号、角色、数据统计） |
| 内容编辑 | 产品系列/分类/产品/案例/新闻/轮播/**关于我们配置** 的增删改查（不含招聘、留言、账号与权限） |
| 客服/HR | **留言管理（联系+应聘）+ 招聘职位管理**（不含账号权限、不含其他内容模块） |

> 说明：内容编辑与客服/HR 的内容边界清晰——前者负责"展示型内容"，后者负责"线索型内容（留言+招聘）"，互不越权。

- **验收**：
  - Given 客服/HR 账号登录，When 访问「管理员管理」或「产品管理」页面，Then 提示无权限。
  - Given Token 过期且 RefreshToken 有效，When 调用管理接口，Then 自动续期或返回 401 并跳转登录。

### 5.2 产品系列管理（P0）
- CRUD：名称、封面、简介、排序、状态（显示/隐藏）。

### 5.3 产品分类管理（P0）
- CRUD：空间/类型分类（客厅/卧室/书房/茶室/餐厅/办公等），支持排序。

### 5.4 产品管理（P0）
- CRUD：归属系列、分类、名称、型号、简介、详情（富文本）、图集、规格参数（JSON）、是否首页推荐、状态。
- `price` 为**展示参考价**（nullable），仅前台展示，不参与任何交易（与 Non-goals 无电商一致）。
- 列表支持筛选与分页、批量上下架。
- **验收**：新增产品必填系列与名称；上传图片后返回可访问 URL（经 `/api/admin/upload`）。

### 5.5 案例管理（P0）
- CRUD：标题、分类（枚举：住宅/工程/商业）、封面、图集、摘要、详情（富文本）、是否标记「新」、排序、状态（显示/隐藏）。
- 列表支持按分类/状态筛选。

### 5.6 新闻资讯管理（P0）
- CRUD：标题、分类（company=企业新闻 / industry=行业资讯）、封面、摘要、正文（富文本）、发布时间、是否置顶、状态（草稿/发布）。
- 列表支持按状态/分类筛选。

### 5.7 招聘管理 · 职位管理（P0）
- CRUD：类型（social=社会招聘 / campus=校园招聘）、标题、部门、城市、薪资（可选）、职责描述（富文本）、任职要求、招聘人数（可选）、状态（上架/下架）、发布时间。
- 列表支持按类型/状态筛选、上下架。

### 5.8 留言管理（P0）
- 列表：按类型（**contact=联系留言 / job_application=应聘留言**）、状态（未处理/已处理/忽略）筛选；应聘留言显示关联职位（ref_id → job 标题）。
- 操作：查看详情、回复（记录回复内容与时间）、标记状态。
- **验收**：回复后留言状态可变更为「已处理」；支持导出（P1）。

### 5.9 首页轮播图管理（P0）
- CRUD：标题、图片、跳转链接（可选）、排序、状态、有效时间（可选）。
- 仅「生效且未过期」的轮播在前台展示。

### 5.10 管理员与角色管理（P0）
- 管理员：新增（用户名、姓名、角色、初始密码）、启用/禁用、重置密码。
- 角色：预置三角色；权限可配置（模块级增删改查开关，P1 可细化到按钮级）。

### 5.11 数据统计（P1）
- 概览：产品/案例/新闻/职位总数、联系留言与应聘留言数量与趋势（近 30 天）、内容更新频率。
- 数据由接口实时聚合，不强制独立统计表。

### 5.12 关于我们配置（P0，v0.3 补全）
负责前台「关于我们」下四页的内容维护，解决此前"内容声称后台驱动却无模块/无表"的需求断点。
- **公司信息（company_info）**：编辑公司名称、LOGO、建厂年份、荣誉数、生产线数、地址、电话、邮箱、微信、ICP 备案号、企业简介（富文本）。驱动首页「企业实力数据」与「联系我们」公司信息。
- **关于Rz / 品牌介绍 区块（about_section）**：按 `code`（overview=关于Rz，brand=品牌介绍）维护标题、富文本、封面图、排序、状态。
- **发展历程（milestone）**：时间轴事件 CRUD（年份、标题、描述、图片、排序、状态）。
- **验收**：修改公司信息后，前台首页实力数据与联系我们页同步更新；新增/编辑 milestone 后发展历程页时间轴同步；未配置时前台显示默认占位文案。

## 九、技术架构（建议默认，可调整）

### 9.1 前端
- **框架**：React 18 + TypeScript + Vite。
- **前台 UI**：Tailwind CSS（轻量、便于品牌定制）。
- **后台 UI**：Ant Design（企业级组件，提升后台开发效率）。
- **路由**：React Router；**状态**：Zustand 或 Redux Toolkit；**请求**：Axios；**富文本**：Tiptap / React-Quill。
- **结构建议**：`frontend/` 下分 `web/`（官网）与 `admin/`（后台）两个应用，或单应用多入口。

### 9.2 后端
- **框架**：FastAPI + Uvicorn；**ORM**：SQLAlchemy 2.0 + Alembic 迁移；**校验**：Pydantic v2。
- **数据库**：PostgreSQL（建议，可换 MySQL）。
- **鉴权**：python-jose + passlib(bcrypt) 实现 JWT；AccessToken（短期）+ RefreshToken（长期，存 Redis 或数据库可吊销）。
- **文件**：图片/文件经 `/api/admin/upload` 上传至本地目录或对象存储（COS/S3），返回 URL。
- **接口文档**：FastAPI 自带 Swagger/OpenAPI。

### 9.3 部署（三环境：dev/test/prod）
- 容器化：Docker + Docker Compose；Nginx 反代 + 静态资源托管。
- CI/CD：GitHub Actions（已连接 GitHub）做构建与部署。
- 环境隔离：配置通过环境变量区分。
