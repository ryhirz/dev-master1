# Rz家居 全栈项目 · 部署手册

> 适用范围：开发 / 测试 / 生产 三环境部署
> 配套：《运行说明.md》（本地启动）、《运营手册.md》（内容维护）

## 1. 架构总览

```
浏览器 ──► Nginx（web/admin 容器内，SPA + 反代 /api）
              │
              ▼
         FastAPI backend (:8000)
              │
         ┌────┴────┐
         ▼         ▼
      PostgreSQL  Redis（可选）
```

## 2. 环境要求

| 环境 | 依赖 |
|---|---|
| 本地开发 | Python 3.11+、Node 20+、SQLite（内置） |
| Docker 部署 | Docker 20.10+ / Docker Compose v2 |
| 生产 | PostgreSQL 16、Nginx、可选 Redis |

## 3. 本地开发启动（SQLite，最快）

```bash
# 后端（dev 自动建库+种子：三角色 + admin/admin123 + 演示数据）
cd backend
python -m venv venv && venv/Scripts/activate      # 首次
pip install -r requirements.txt                     # 本机无 C 编译则跳过 psycopg2-binary
ENV=dev uvicorn app.main:app --port 8000

# 前台（5173）
cd frontend/web && npm install --legacy-peer-deps && npm run dev

# 后台（5174；本机 Windows 推荐 preview，dev 可能触发 safe-delete 崩溃）
cd frontend/admin && npm install --legacy-peer-deps
npm run build && npm run preview -- --port 5174
```

## 4. Docker 一键起（推荐演示/生产预演）

```bash
docker compose up --build
# 前台 http://localhost:8080 ｜ 后台 http://localhost:8081 ｜ API 文档 http://localhost:8000/docs
```

服务编排：`db(postgres:16)` + `backend` + `redis(7)` + `web(nginx)` + `admin(nginx)`。
- 首次启动 backend 自动执行迁移并幂等种子（ENV=prod 时建议改由 CI/运维执行 alembic）。
- 上传目录挂载卷 `uploads`（`UPLOAD_DIR` 可用环境变量覆盖）。
- `SECRET_KEY` 通过环境变量注入：`SECRET_KEY=... docker compose up -d`。

## 5. 生产部署（PG + Nginx + CI）

### 5.1 数据库迁移
```bash
# 生产 PG（sslmode=require、最小权限账号）
DATABASE_URL=postgresql+psycopg2://app_user:***@db-host:5432/rz_home?sslmode=require \
  alembic upgrade head
# 幂等种子（三角色 + 默认超管；首次部署后务必改密）
python -c "from app.core.db import init_db, seed; init_db(); seed()"
```

### 5.2 密钥与配置（环境变量，禁止落库明文）
| 变量 | 说明 |
|---|---|
| `SECRET_KEY` | JWT 签名密钥，生产必改（≥32 位随机） |
| `DATABASE_URL` | SQLAlchemy 连接串 |
| `CORS_ORIGINS` | 允许的前台/后台域名，逗号分隔 |
| `UPLOAD_DIR` | 上传落盘目录（生产挂卷/对象存储前先抽象） |
| `BCRYPT_ROUNDS` | 密码哈希轮数（默认 12；性能敏感可调 10，见 M5_SUMMARY §性能） |

### 5.3 CI 流程（GitHub Actions，`.github/workflows/ci.yml`）
- PR：后端 SQLite 单测 + 前端 typecheck/build；backend job 内起 PG service 跑集成测试。
- 合 main：构建镜像 → 测试 → 人工确认 → prod（生产发布流水线按团队规范补充）。

### 5.4 Nginx 反代示例（如需独立 Nginx 网关）
```nginx
server {
  listen 80; server_name www.rzhome.com;
  location / { proxy_pass http://127.0.0.1:8080; }          # web
  location /admin/ { proxy_pass http://127.0.0.1:8081; }    # admin（可选子路径）
  location /api/ { proxy_pass http://127.0.0.1:8000; }
  location /static/ { proxy_pass http://127.0.0.1:8000; }
}
```
